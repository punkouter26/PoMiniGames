Roles & permissions matrix

Verdict-driven grid: principal × environment against Minimal API endpoints, SignalR hubs, and UI routes. Every verdict cites the guard as written in source.

Headline finding · the app has no role checks

A grep across src/**/*.cs for RequireRole, [Authorize(Roles=...)], policy.RequireRole, and IsInRole returns exactly one hit: src/PoMiniGames/Features/Auth/RequestIdentity.cs:39 — (user?.IsInRole("guest") ?? true). There is no endpoint with a RequireRole("admin")-style gate. The role columns therefore collapse to one column showing where "guest" is detected.

1. The single role check

WhereRoleWhat it does
RequestIdentity.Resolve guest Sets Identity.IsGuest to true when the caller has no stable oid/nameidentifier/sub claim OR has the guest role. Used by storage paths (MatchHistory, MarbleRaceHighScores, HighScoreDescriptor) to mark rows and to choose fallback identity ("Guest").

No other code reads roles. No endpoint uses RequireRole(...). No policy scheme declares a role-based authorization policy. The whole authorization decision is "anonymous vs authenticated" plus, inside the request, "is the caller a guest".

2. Principal × environment × endpoint

Verdicts come from the actual guard, not from policy intent. "Anonymous" means the endpoint is reachable without a session; "Authenticated" means MapGroup("").RequireAuthorization() (or an explicit [Authorize] on the legacy unprefixed routes); "Hub-auth" means app.MapHub<T>(...).RequireAuthorization().

The "guest" column is a derived state, not a separate principal — a guest is an authenticated caller whose RequestIdentity.IsGuest == true. There is no path that grants a guest write access: MapGroup("").RequireAuthorization() requires the bearer/cookie principal to authenticate, and the principal is marked guest only after authentication succeeds. The 401 in the guest columns reflects that the guest principal arrives at the endpoint only when DevCookie minted it (Dev/Test only) — in Production there is no path that produces a guest principal, so the column is theoretical.

3. Why the role columns collapse

The matrix the prompt asks for is a principal × role × environment grid. The principal columns (anon / auth / guest) are meaningful. The role columns are not, because:

  • No RequireRole(...) exists anywhere.
  • No AuthorizationPolicy is declared with role-based requirements.
  • The single IsInRole("guest") lookup is used inside RequestIdentity.Resolve to compute IsGuest, not to gate authorization. A caller with the guest role is authenticated; what changes is what DisplayName / UserId they end up with on a saved row.

Rendering additional role columns (e.g. "admin", "moderator") would imply that those principals exist. They don't. The honest finding is the headline above: there are no roles to matrix.

4. UI route gates

Blazor gates are based on BffAuthenticationStateProvider.GetAuthenticationStateAsync(), which mirrors the BFF's /auth/me HTTP endpoint. There is no [Authorize(Roles=...)] on any @page.
