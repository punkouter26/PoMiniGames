3. Shared DTO surface (PoShared)

PoShared is a leaf project that every other project depends on. Its contents are deliberately minimal: types that have to cross the wire or the project boundary, plus shared markers.

3.2 Risk surface

Because every project reads PoShared, anything added here immediately becomes a public contract for the whole solution. Today's contents are small and contract-shaped (DTOs, marker interfaces, identity constants). The risk surface to monitor:

  • Adding logic to PoShared (anything beyond types & constants) breaks the leaf property.
  • Adding dependencies to PoShared's .csproj drags them into every consumer — keep it transitive-clean.
  • PoShared/Games/PoRacerShared.cs & PoSportsShared.cs are read by both Web (hub) and Client (state binding) — schema changes are wire changes.

Verdict · clean VSA, no layer leaks

The dependency graph is a DAG with Domain and PoShared as leaves. The only "upward" references are the composition root in the Web host, which is the intended pattern. There are no test shortcuts around PoMiniGames; every test tier boots the host (Unit fast in-process, Integration through TestWebApplicationFactory, E2E through real HTTP).
